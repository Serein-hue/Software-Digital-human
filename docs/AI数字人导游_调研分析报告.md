# 景区导览服务AI数字人

**竞品调研 · 技术选型 · 需求分析报告**

第十五届中国软件杯 A5赛题 | 2026年5月

## 一、政策环境与行业背景

### 1.1 政策驱动

国家层面对文旅数字化给予了高度重视和明确支持：

- 《“十四五”文化和旅游发展规划》明确要求加强数字技术应用，发展数字体验产品，打造沉浸式旅游体验新场景
- 《文化和旅游部关于推动数字文化产业高质量发展的意见》将数字文旅列为数字经济十大应用场景之一
- 2025年7月，文化和旅游部批准筹建“文旅大模型及数据智能服务技术创新中心”，依托中国移动建设，专攻大模型在文旅的工程化落地
- 各省市积极跟进：浙江推进“入浙游”大模型、甘肃推出“一部手机游甘肃”、湖南打造数字文博大平台“山海”等

> 政策窗口期明确：行业专家指出，未来三到五年将是AI重塑文旅产业格局的关键窗口期。

### 1.2 市场规模

2025年我国数字文旅市场规模预计突破7万亿元。2024年使用AI规划行程的游客占比已从17%飙升至68%，41-55岁群体成为高频用户主力。全国5A级景区中已有83%部署了沉浸式体验项目。

### 1.3 行业痛点（直接对应赛题场景）

| 痛点类别 | 具体表现 | AI数字人的解法 |
| --- | --- | --- |
| 导游资源稀缺 | 黄金周/旺季专业导游供不应求，中小景区常年无专职导游 | 7×24h在线，无人力成本上限 |
| 信息单向传递 | 传统录音导览内容固定，无法回答个性化问题 | RAG知识库支撑多轮问答 |
| 缺乏情感连接 | 设备冰冷，缺乏真人导游的亲切感和互动 | 表情、语音、口型三位一体的拟人化交互 |
| 管理盲区 | 无法量化评估服务质量，难以精准获取游客真实反馈 | 交互数据自动沉淀，生成感受度报告 |
| 内容更新滞后 | 传统导览设备更新成本高，内容老化 | 知识库管理后台可随时热更新 |

### 2.3 竞品共性不足（我们的差异化机会）

- 多数商业产品是“大而全”的平台产品，中小景区落地成本高、周期长
- 知识库管理对景区运营人员不友好，更新维护专业门槛高
- 游客感受度分析停留在基础统计层面，缺乏情感趋势洞察和可操作的服务建议
- 数字人形象高度依赖定制服务，景区自主配置能力弱
- 高并发场景下响应延迟和稳定性问题普遍存在

## 四、用户群体与需求分析

### 4.1 核心用户群体

| 用户类型 | 典型画像 | 核心痛点 | 使用场景 |
| --- | --- | --- | --- |
| 普通游客（散客） | 25-55岁，手机为主要交互设备，对景区文化有一定兴趣 | 不知道景区有哪些值得看的，排队等导游时间长，问题得不到及时回答 | 进入景区后扫码/打开App自助导览，随时随地提问 |
| 亲子家庭游客 | 带小孩出游，希望寓教于乐，对趣味性要求高 | 孩子注意力难以集中，传统讲解太枯燥 | 互动游戏化讲解，数字人以儿童友好语气回答 |
| 银发族游客 | 50岁以上，可能不熟悉智能设备，听力可能有下降 | 操作复杂、字体小、响应慢 | 适老化界面，大字体，语音为主交互 |
| 文化爱好者/研学团体 | 对历史文化有深度探索需求，问题专业性强 | 普通导览深度不足，无法满足深度问答 | 深度知识问答，关联历史典故、文献资料 |
| 景区管理员 | 负责日常运营，非技术背景 | 知识库更新繁琐，数据看不懂，报告无实际指导价值 | 简洁的管理后台，一键上传文档，清晰的数据看板 |

### 4.2 需求优先级（MoSCoW分析）

#### Must Have（刚需，分数直接挂钩）

- 语音+文本双模态输入，数字人语音+口型同步回答
- 基于景区知识库的准确问答（准确率≥90%）
- 个性化路线推荐（按兴趣分类：历史/自然/美食等）
- 知识库管理后台（文档上传/更新/删除）
- 游客感受度报告（情感分析+关注点统计）
- 数据大屏（服务人次/热门问答/满意度趋势）

#### Should Have（强需求，提升评分）

- 数字人形象配置（外观/服装/声音，与景区文化贴合）
- 多轮对话上下文记忆（追问能力）
- 响应延迟控制在5秒以内
- 移动端H5/小程序适配

#### Could Have（弱需求，创新加分项）

- 照片识景功能（上传照片自动识别景点并讲解）
- 多语言支持（英语/日语等，服务入境游客）
- 自动生成个性化游记（离景时发送到手机）
- 景区实时客流提示（结合安防数据）

#### Won't Have（明确排除，控制边界）

- 票务购买、支付功能（超出赛题范围，引入合规风险）
- 用户账号体系/社交功能（增加复杂度，非核心）
- VR/AR沉浸式体验（硬件依赖强，Demo阶段成本过高）
- 全身3D数字人实时渲染（计算资源需求远超比赛展示需要）

## 五、产品边界与运转逻辑

### 5.1 产品不做什么

明确产品边界是拿一等奖的关键——评委最担心的是“大而空”。我们的原则是：

- 不做通用旅游平台，只服务“景区内”的导览场景
- 不替代景区票务/电商系统，只做导览+问答+数据分析
- 不自研底层大模型，基于成熟开源模型API调用
- 不做全身实时3D数字人，用2D数字人（EchoMimic/MuseTalk）在视觉效果和技术可行性间取最优平衡
- 不做游客账号登录体系，匿名使用降低使用门槛

### 5.2 系统整体运转逻辑

整体架构分为三层：

- **游客交互层**：H5/小程序（扫码进入）+ 景区终端大屏。游客说话或输入文字 → Whisper转文字 → 意图识别 → RAG检索知识库 → 大模型生成回答文本 → TTS转语音 → EchoMimic驱动数字人口型/表情 → 渲染输出
- **AI服务层**：大模型（Qwen/DeepSeek）+ RAG知识库（RAGFlow/LangChain）+ 情感分析模块 + 数字人渲染引擎，部署在服务器/云端
- **管理后台层**：知识库管理（文档上传/解析/向量化）+ 数字人形象配置 + 数据大屏（实时数据可视化）+ 游客感受度报告（定时生成）

### 5.3 核心数据流与埋点设计

| 埋点事件 | 触发时机 | 采集数据 | 用途 |
| --- | --- | --- | --- |
| session_start | 用户开始对话 | 时间戳、入口来源（扫码/手动）、设备类型 | 服务人次统计、峰值分析 |
| query_sent | 用户发送问题 | 问题文本、输入方式（语音/文字）、时间戳 | 热门问答统计、问题分类 |
| answer_generated | 系统返回回答 | 回答文本、响应延迟ms、知识库命中率 | 准确率监控、延迟优化 |
| route_recommended | 触发路线推荐 | 游客选择的兴趣标签、推荐路线ID | 路线受欢迎程度分析 |
| feedback_given | 用户点赞/踩 | 问题ID、评价类型（正/负） | 满意度趋势、质量监控 |
| session_end | 对话结束/超时 | 会话时长、轮次数、最后交互时间 | 用户留存分析 |
| emotion_score | 每轮对话后情感分析 | 情感极性（正/中/负）、情感强度 | 游客感受度报告原始数据 |

### 5.4 管理后台功能清单

| 模块 | 功能点 | 优先级 |
| --- | --- | --- |
| 知识库管理 | 文档上传（支持PDF/Word/TXT）、解析预览、分类标签、版本管理、热更新 | P0 |
| 数字人配置 | 形象选择（预置多套景区风格皮肤）、声音音色配置、欢迎语/口头禅自定义 | P0 |
| 数据大屏 | 今日/本周服务人次、热门问题Top10、平均响应时长、游客满意度实时指数 | P0 |
| 感受度报告 | 周报/月报自动生成、情感趋势折线图、高频负面反馈词云、改进建议摘要 | P0 |
| 对话记录查询 | 按时间/关键词搜索历史对话、标记异常回答、人工纠正知识库 | P1 |
| 系统配置 | 响应语言设置、敏感词过滤规则、最大会话时长、并发限制 | P1 |
| 账号权限管理 | 管理员账号、景区操作员账号、只读查看权限分级 | P2 |

## 六、推荐技术架构与开发路径

### 6.1 推荐技术组合（国产+开源优先）

| 层次 | 推荐方案 | 备选方案 | 理由 |
| --- | --- | --- | --- |
| 大模型 | DeepSeek-V3 API | Qwen2.5-72B API | 中文能力强，成本低，赛题期间API稳定 |
| 语音识别(ASR) | Whisper large-v3 | FunASR（阿里） | 赛题推荐，开源，中文准确率高 |
| 语音合成(TTS) | CosyVoice / Edge TTS | ParaTTS（赛题推荐） | 中文自然度佳，支持音色克隆 |
| 数字人驱动 | EchoMimic V2 | MuseTalk（实时更好但更重） | 半身动画效果好，推理速度快 |
| RAG框架 | RAGFlow + Milvus/Chroma | LangChain + FAISS | RAGFlow文档解析能力强，知识库管理界面友好 |
| 后端框架 | FastAPI (Python) | SpringBoot (Java) | 与AI生态无缝集成，开发效率高 |
| 前端 | Vue3 + Vite | React | 小程序可用uni-app一套代码多端 |
| 数据库 | PostgreSQL + Redis | MySQL + Redis | PostgreSQL对JSON支持好，便于存交互日志 |
| 部署 | Docker Compose | K8s（规模化后） | 比赛阶段快速部署，单机可运行 |

### 6.2 开发优先级建议（冲刺时间轴）

- **第1-2周（MVP核心）**：知识库RAG问答 + 文字交互 + 基础数字人渲染联调，确保问答准确率先跑通
- **第3-4周（语音打通）**：接入Whisper+TTS，实现语音全链路，优化延迟到5秒以内
- **第5-6周（后台建设）**：知识库管理后台 + 数据大屏 + 情感分析报告功能
- **第7-8周（体验打磨）**：数字人形象优化、个性化路线推荐、多轮对话优化、压测
- **第9周（文档&视频）**：设计文档、演示视频制作、PPT整理，这个阶段占10分不能忽视

### 6.3 差异化创新点建议（冲刺一等奖）

- **“情绪感知”回答策略**：通过情感分析判断游客当前情绪（疲劳/兴奋/困惑），动态调整回答风格和内容长度
- **景区文化IP人格化**：知识库不只存事实，还存“导游人格设定”（幽默/严肃/儿童友好），让数字人有性格
- **“问题预判”功能**：基于同一景点的高频历史问题，主动推送“你可能还想知道”的相关信息
- **管理后台的“智能运营建议”**：不只展示数据，用AI对数据做解读，给出“本周游客对XX展区评价偏低，建议检查讲解词”等具体建议
